Code + design review

What is strong, what should move next

The product boundaries are sound; the next gains come from reducing concentration in the two largest orchestration files and hardening trust.

Strong now

Architecture worth preserving

  1. 01Pure, deterministic rules. Arena, blast, danger, bots, powerups, layout, and scoring run without Phaser and carry focused unit tests.
  2. 02Explicit UI/engine bridge. React and Phaser exchange typed data through GameEvents and registry state.
  3. 03Validated server inputs. Match, leaderboard, visitor, and music payloads are checked before MongoDB writes.
  4. 04Coherent product language. HUD, dialogs, bots, audio, scores, and responsive controls share one neon arcade system.

Next hardening

Review findings to address

  1. 01Decompose orchestration. ArenaScene.ts is 1,019 lines and GameShell.tsx is 888; extract round/bomb actor systems and individual dialogs/hooks.
  2. 02Protect competitive scores. Schema validation prevents malformed payloads, but the browser still reports winner, duration, and blocks cleared.
  3. 03Add browser regression coverage. Unit coverage is healthy; the documented load/move/bomb/post flows still need automated end-to-end checks.
  4. 04Remove layout drift risk. Reserved HUD/control dimensions duplicate CSS values; measure rendered bands and pass them across the existing bridge.
  5. 05Protect public write routes. Custom music creation is validated but has no authentication or rate limit; gate or disable that endpoint before broad public use.
